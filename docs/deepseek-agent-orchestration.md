# DeepSeek API智能体编排方案

## 实现目标

由DeepSeek API选择业务工具、根据工具结果决定下一步并组织回答。查询、预测、候选溯源、知识检索和建议草稿在本机执行；现场确认与处置由人工完成。

对应报名表“大模型组织数据查询、模型调用与专业资料检索”，验收对象是模型生成的工具调用及其真实执行结果。API连通、工具接口存在和模板回答分别记录。

## 调用流程

1. 本机校验用户、来源、所选测点和执行时钟，提取任务类型与已知对象。
2. 为DeepSeek生成任务描述、可用工具与对象别名。原始问题、旧对话和本机路径保存在本机。
3. DeepSeek返回`tool_calls`，本机校验JSON参数、对象归属和时间范围后执行。
4. 完整业务结果进入本机结果卡；白名单摘要进入下一轮DeepSeek请求。
5. DeepSeek继续选择工具或形成回答，本机将引用别名关联到可回查的原始依据。

单次最多5轮、12次工具调用和60秒执行预算；保留取消、中断记录及失败后的业务结果。API失败标记为失败或部分完成。

## 工具职责

| 工具 | 本机执行 | API结果范围 |
|---|---|---|
| `query_series` | 查询当前时钟可见的监测序列 | 样本数、有效值统计、最小/最大/均值/末值 |
| `run_prediction` | 调用已登记预测模型 | 状态、运行别名、预测摘要及模型语义 |
| `get_forecast` | 读取本会话可见的预测结果 | 有界预测摘要及其单位 |
| `query_events` | 查询可见事件及修订 | 事件别名、类型、等级及相对时间 |
| `get_event_evidence` | 关联监测、规则、预测与候选溯源 | 获准统计、候选分组与概率含义、缺失项 |
| `search_documents` | 检索本机资料并核验版本 | 公开条文原文；私有条文仅提供本机引用状态 |
| `draft_advice` | 根据本机依据创建建议草稿 | 草稿状态及引用别名 |
| `get_case` | 读取处置阶段和记录 | 阶段与记录数量 |

主动简报复用相同投影规则，仅提供事件依据、预测、资料检索和处置查询四类只读工具。

## 配置与数据范围

合成隔离来源继续使用`EVENT_BRIEF_ALLOWED_SOURCE_IDS`。

真实来源单独使用`AGENT_REAL_DATA_MODE=summary`和`AGENT_REAL_SOURCE_IDS`。两项都符合才进入摘要编排；默认`disabled`、来源列表为空。正式启用以用户明确批准的外发范围为准。

摘要路径使用每次任务独立的对象别名与虚拟时钟；完整时序、私有规程正文、人员操作正文、密钥及文件路径保存在本机。公开资料在每轮请求前重新核验授权和适用性。

当前结构化任务描述通过本机规则提取任务类型、对象及时间要求；其可识别范围需要随独立问题集扩充。DeepSeek根据该描述自主选择工具和后续步骤。

本方案使用DeepSeek API；已有本机文本向量模型和重排模型继续承担知识检索。

## 验收

- 先运行失败测试，再实现路由与投影。
- 用离线适配器验证模型返回的工具名、参数和调用顺序确实触发本机业务服务。
- 检查每轮请求均未包含原始问题、真实标识、原始行、私有正文及未知扩展字段。
- 验证权限、时间回映、引用回查、取消、预算、公开条文撤权及API故障。
- 用完全合成数据调用真实DeepSeek API，记录模型、调用轮数、工具步骤和回答；真实来源验收单独记录。

接口依据：[DeepSeek Chat Completions文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。
