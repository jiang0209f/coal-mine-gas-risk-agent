## 资料上传与原文定位

安全管理角色上传PDF、DOCX、TXT或MD原件，每份上限20MiB。服务保存文件SHA-256、大小、上传人和工作面范围；HTTP接口使用`file_id`，读取原件时复核摘要。

导入时填写标题、来源、版本和适用工作面，关联已上传`file_id`。PDF保留物理页码，DOCX保留段号或表格定位，TXT/MD保留行号；长文本分段后继续保留原始定位。资料初始为`pending_review`，人工审核通过后进入检索。检索采用本地文本匹配，支持以空格或常用分隔符输入多个关键词。

| HTTP接口 | 用途 |
| --- | --- |
| `POST /api/references/files` | 上传原件，返回文件编号、摘要和范围 |
| `GET /api/references/files/{file_id}` | 查询原件元数据 |
| `GET /api/references/files/{file_id}/content` | 经认证读取原件 |
| `POST /api/references/imports` | 登记文件内容或内联原文，形成待审资料版本 |
| `GET /api/references` | 查询资料和经验清单 |
| `GET /api/references/{entry_id}?version=...` | 查看指定版本与原文片段 |
| `POST /api/references/{entry_id}/review` | 安全管理角色审核指定版本 |
| `POST /api/references/search` | 在当前工作面检索已审核、有效的最新资料 |

## 现行版本与两个时间

资料有效期按服务器当前时间`now_utc`核验，使用可注入时钟进行测试。适用范围中的`valid_from`和`valid_to`使用带时区的时间，区间为`[valid_from, valid_to)`；尚未生效的资料不能批准，继续保持待审。

同一`entry_id`的新版本通过审核后，旧批准版本标为`superseded`。旧版本原文和既有引用继续保存，供已形成的建议、动作及快照回查；新检索和新建议使用当前版本。

监测数据时间与知识核验时间分别记录。例如，回放2022年监测数据时，建议的`data_as_of`仍对应该事件数据，`knowledge_as_of`记录本次核验资料的当前时间。页面分别展示这两个时间，当前研判采用当前有效知识。

现有31002工作面作业规程按用户2026-11-04确认暂作现行资料，后续取得新版本后替换。该现行性记录写入材料元数据，原件正式入库后仍按待审流程核对条文、工作面和定位。研究草稿保留草稿性质。

## 建议、处置与经验

1. 选择实际预警事件，查看冻结修订及监测、预测和候选溯源依据。
2. 检索资料并打开原文，选择引用后通过`POST /api/advice`生成建议版本。建议保存事件修订、资料版本、原文定位和两个时间。
3. 人工确认事件；安全管理角色审核具体`advice_id/version`，选择批准或拒绝。拒绝后可生成新版本再审。
4. 对已批准且仍适用的建议记录执行，再提交反馈。事件修订变化或引用资料失效、被替代时，重新生成并审核建议。
5. 人工复核后冻结快照，保留会话、来源、事件修订、每次动作的事件快照、执行建议版本、反馈和原始引用。
6. 基于复核快照提交经验，经验初始待审。安全管理角色审核通过后进入检索；演练经验保留`rehearsal`性质，不进入实时现场建议。

通风、瓦斯治理和安全管理角色按既有权限登记人工动作；资料、建议和经验审核由安全管理角色执行。自动工具读取依据和生成草稿，人工操作通过处置接口记录。

| HTTP接口或返回字段 | 用途 |
| --- | --- |
| `GET /api/cases/{event_id}?session_id=...` | 读取阶段、建议版本、审核记录、待办与归档 |
| `POST /api/cases/{event_id}/actions` | 确认、审核建议、登记执行、反馈及复核 |
| `current_event_revision`、`advice_validity` | 标明当前事件修订和建议是否过时 |
| `reviewed_snapshot` | 返回已复核冻结快照；未复核时为空 |
| `POST /api/experiences` | 从已复核处置单提交待审经验 |
| `POST /api/experiences/{experience_id}/review` | 审核指定经验版本 |
